# Reusable groups

- `SmartGroup.color` stores a named semantic color (or a legacy CSS/hex color). `SmartGroupPalette` resolves it in both windows. Nil uses the app accent. Create, edit, icon-edit and export/import must carry color and `preservesItems` together.
- `SmartGroupItems` owns manual UI membership, full-group item order and counts. Same-group assignment is a no-op; moving a selection keeps its supplied visual order as one block. Manual UI assignments append after existing group items. Membership removal/group deletion clears `ClipItem.groupSortOrder` without deleting content or changing history timestamps.
- `ClipItem.groupSortOrder` is an optional persisted integer for SwiftData additive migration. Older items have nil ranks and fall back to last-used chronology with item ID as a stable tie breaker. First assignment/reorder normalizes the full destination group, including members outside the loaded page.
- `ClipItemStore` applies `SmartGroupItems.sqlOrderBy` before SQL LIMIT/OFFSET only when filtering by a group. Manual positions outrank pin/last-used changes inside groups. Other history keeps its existing chronology/pin preference. Both window caches must skip time headers/regrouping when `store.groupName != nil`.
- Internal item/selection drags use `ClipItemDrag.type` (`com.lifedever.pastememo.clip-items`) and a current-process session token. Ordinary text and sidebar type/group reorder cannot assign clips. Resolve IDs from the destination ModelContext; stale/missing IDs are ignored. Sensitive text is omitted from external drag representations.
- Sidebar tabs accept assignment; All accepts membership removal. Native group lists accept insertion-before/append drops, while bottom cards accept the equivalent shared APIs. Context move-to-beginning/end actions provide an alternative to pointer dragging. Group-list reorder remains separate.
- Export v2 and streaming backups include optional `groupSortOrder`; old v1/v2 payloads lacking it still import with nil ranks. Backups share the DataPorter path. Existing group merge behavior is unchanged.
- Deletion snapshots restore `groupSortOrder` alongside membership. Duplicate capture preserves an existing member's rank and carries the incoming rank when inheriting membership. Automation assignment keeps same-group actions idempotent and clears stale ranks when moving to another group. Its existing per-item capture/manual-rule path leaves moved items unranked with history fallback until manual assignment/reorder normalizes the group; rule batches do not promise visual block order. Existing ranked members remain stable.
- Tests use separate in-memory or temporary on-disk stores, never the production history. SQL readers honor the configured ModelContext store URL. Cover counts/retention/no-op, multi-selection order, >50-item SQL pagination, timestamp updates, disk reopen, deletion, old imports and streaming backup restore.
